InsureX · Test Case 27
Bonus 2 · Session memory

Every chat remembers its own conversation, even after a restart

LangGraph checkpointer: thread_id = session_id; state is saved after every node

Separation

Each session is its own thread. Bob asks "what did I ask before?" and gets "no record", while Alice's chat is untouched.

Recent + summary

The last 8 messages go to the LLM verbatim. Past 12 unsummarised messages, the update_memory node folds older ones into a running summary, so long chats aren't forgotten.

Persistence

SQLite on disk: close the app, reopen the chat, and it continues. Follow-ups like "and for medical expenses?" are resolved from memory.

  • Chats are listed on the server with an auto title and date; they can be renamed and deleted (delete erases the memory; saved leads stay as business records).
  • One turn at a time per session (async lock), so two browser tabs can't interleave one conversation.
Tested: after 14 messages the summary kept "Ploy, 32, pharmacist, PA Plus Silver 1,890 THB", and the agent answered "what was the first price you quoted me?" correctly.

Lessons learned

Three problems that testing caught, and how I fixed them

Each was found by the evaluation or the demo, not by reading the code

1 · "Car insurance" scored 0.52

Vector similarity can't detect off-topic questions. Fix: an LLM grader with a strict "directly answers" rule, plus a retry loop and fallback.

2 · Structured output was unreliable

Ollama's JSON-schema mode returned null for "nurse" and the income, so I switched to tool calling. But the model sometimes skips the tool call (88% accuracy). Fix: retry, then JSON mode, then a safe default, which reached 100%.

3 · "Hi, I'm Ploy" started a lead

A self-introduction isn't interest. Fix: details count as a lead only after interest, or when a phone number is given. A Thai demo turn caught the first version of the fix.

The lesson: with LLM systems, an evaluation set and a replayable demo are what make changes safe.
InsureX · Test Case 213
Next steps

From working prototype to production

What I would do with the real documents and more time

  • Real PDFs: re-ingest, OCR scanned Thai pages, and rebuild the evaluation set with the sales team.
  • Better retrieval: hybrid BM25 + vector search and a cross-encoder reranker for long documents.
  • Monitoring: LangSmith or OpenTelemetry tracing of every node, plus answer feedback buttons in the chat.
  • Security & PDPA: log-in per sales agent, encrypt leads, consent text before collecting details, retention rules.
  • Deployment: Docker Compose (Ollama + API + UI), or a hosted model if latency matters more than locality.
  • CRM: push leads from the MCP tool straight into the CRM instead of SQLite.
